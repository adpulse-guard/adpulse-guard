GAM ad slot not requesting? A practical GPT troubleshooting guide

A container on the page is not proof that an ad request was sent. Follow the evidence from GPT setup to the request and render stages before deciding whether delivery is broken.

AdPulse Guard technical guide · November 2026

First, define what “not requesting” means

A visible placeholder, a defineSlot() call and a completed ad request are different things. A slot may be registered in GPT but held until consent, viewability, user interaction or an explicit refresh(). An absent request is not necessarily a defect.

Start with a specific page, viewport, slot ID and expected behavior. Reproduce the issue after any consent choice has been made and allow lazy-loaded placements to enter the relevant loading range.

1. Confirm that Google Publisher Tag initialized

In the browser console, inspect window.googletag?.apiReady and window.googletag?.pubadsReady. If GPT never initializes, check whether gpt.js is blocked, missing or prevented from running. A page that loads a GTM container does not necessarily load GPT.

In DevTools → Network, look for the GPT script and check for blocking errors. If consent management controls advertising scripts, test the state in which ads are expected to run.

2. Compare registered slots with DOM containers

When GPT is ready, list the slots and the elements they target. Use this read-only snippet for ordinary in-page slots:

const slots = window.googletag?.pubads?.().getSlots?.() || [];
console.table(slots.map(slot => ({
  id: slot.getSlotElementId(),
  adUnit: slot.getAdUnitPath(),
  inDOM: !!document.getElementById(slot.getSlotElementId())
})));

For in-page slots, a missing matching container deserves investigation. However, a registered slot without a DOM element is not automatically a failed request: it may be intended for another template, created before rendering, or use an out-of-page format.

3. Check requests at the slot level

In DevTools → Network, filter for /gampad/ads. This is useful request evidence, but do not equate the number of HTTP requests with the number of ad slots. Google Publisher Tag can bundle multiple slots into one request through single request architecture.

For instrumented pages, GPT’s slotRequested event provides slot-level evidence. A monitoring listener must be attached before the relevant event; adding one after the request cannot reconstruct past events. Compare a particular slot’s request evidence with its registration and DOM state.

4. Check intentional request delays

  • Consent: An ad request may be postponed until a consent decision is available.
  • Lazy loading: Below-the-fold placements may not request until the user approaches them.
  • Initial load disabled: If disableInitialLoad is enabled, display() alone does not fetch an ad; a later refresh() is required.
  • Conditional templates: Mobile, desktop and article layouts may intentionally activate different slots.

Do not “fix” a missing request by calling refresh() in production without understanding the publisher’s setup and refresh policies.

5. Separate missing requests from empty responses and render problems

These stages need different investigations:

No request observedCheck initialization, triggering, consent and lazy-load conditions.
Request sent, empty renderReview eligibility, demand, targeting and the response path; an empty response is not proof of a code failure.
Response received, ad not visibleCheck creative rendering, slot dimensions, collapsed containers and overlapping page content.

GPT exposes slotResponseReceived and slotRenderEnded events. The slotRenderEnded event includes an isEmpty field, which helps distinguish an empty result from other rendering outcomes.
